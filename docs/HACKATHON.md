# Shipaton 2026 submission checklist

Target: RevenueCat Shipaton Next Gen Award.

## Repository requirements

- Public GitHub repository.
- Visible open-source [LICENSE](../LICENSE).
- Setup instructions in [README](../README.md) and [docs/SETUP.md](SETUP.md).
- No real local config, signing material, service credentials, or child data in
  current files or Git history.
- Public repo security features enabled: secret scanning, push protection,
  Dependabot alerts, and private vulnerability reporting.

## Product proof to verify

- RevenueCat Test Store purchase works in fresh development build.
- `bearfetch_progress_insight_lifetime` is attached to current offering as
  `$rc_lifetime`.
- `progress_insight_requests` entitlement activates after purchase and after
  Restore purchase.
- Demo build matches video and screenshots.

## Devpost assets

- Project name, tagline, English description, technology tags, and RevenueCat
  project ID.
- Public YouTube or Vimeo demo. Essential flow under two minutes.
- 1024 x 1024 app icon.
- At least one 1179 x 2556 frameless app screenshot.
- Team members added before submission.
- Explain target award, child-learning problem, course flow, and RevenueCat
  purchase flow.

## Next Gen exception

Next Gen accepts public repository plus demo instead of store listing. Use a
verifiable academic email. Other Shipaton categories still require live app
store link, US availability, and working RevenueCat integration.

## Owner actions before public switch

1. Confirm MIT license ownership wording is acceptable for BearFetch.
2. Confirm rights to every illustration, font, icon, screenshot, and brand
   asset in this repository.
3. Run full Git-history secret scan. Revoke and rewrite history if anything
   sensitive ever entered Git.
4. Commit reviewed work, push `main`, then change GitHub repository visibility
   to Public.
5. Enable GitHub security features listed above.
6. Publish legally reviewed Privacy Policy and Terms before any public
   child-directed app distribution. Complete applicable COPPA/GDPR-K review.
7. Record final demo, upload public/unlisted video, submit Devpost, then open
   submitted entry and test every public link while logged out.
