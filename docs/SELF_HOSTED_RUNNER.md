# BearFetch self-hosted GitHub Actions runner

This private repository uses a self-hosted macOS ARM64 runner to avoid
GitHub-hosted Actions billing. It executes trusted code from `main` only.

## One-time registration

1. In GitHub, open `alwayskumar-global/bearfetch-app` → **Settings** →
   **Actions** → **Runners** → **New self-hosted runner**.
2. Select **macOS** and **ARM64**. Run the exact download, extraction,
   `./config.sh`, and token command generated by GitHub in a dedicated folder
   outside this repository, for example `~/actions-runner/bearfetch`.
3. Keep the default labels: `self-hosted`, `macOS`, and `ARM64`. The workflows
   require all three labels.
4. When prompted for a runner group, use **Default** unless you have created a
   locked-down BearFetch-only group.
5. Run `./run.sh` once and confirm the runner appears **Idle** in GitHub.

## Host prerequisites

Install and verify these on the Mac account that runs the service:

```bash
flutter --version
flutter doctor -v
java -version
sdkmanager --licenses
```

The runner needs Flutter 3.41.4-compatible tooling, JDK 17, Android SDK build
tools, Android platform 37, and accepted Android SDK licenses. The CI workflow
downloads the pinned Flutter SDK itself, but Android SDK and JDK availability
remain host requirements.

## Persistent service

After the first interactive run succeeds, install the generated launchd
service from the runner directory:

```bash
sudo ./svc.sh install
sudo ./svc.sh start
./svc.sh status
```

Use a dedicated macOS account where possible. Full Disk Access is not
required. Do not run the service as an administrator unless GitHub's runner
installer explicitly requires it.

## Security rules

- Keep `pull_request` triggers disabled for self-hosted workflows.
- Do not add repository secrets to logs, files, artifacts, or `dart-define`
  output.
- Do not register a runner on a shared or untrusted computer.
- Keep the runner directory and its `.credentials` file private to its macOS
  service account.
- Release builds are manual only and remain blocked until their signing
  material is configured.

## Verify

Push the workflow change, then open **Actions → CI → Run workflow**. Both
`quality-and-android` and `secret-scan` should be claimed by the self-hosted
macOS ARM64 runner. Only then enable branch protection required checks.
